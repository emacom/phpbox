# Magento and Mage-OS

The `magento` and `mageos` platforms share the code in `platforms/magento/magento.sh`. They differ in the package repository and the key requirement.

| Platform | Repository | Keys | Box name prefix |
|---|---|---|---|
| `magento` | `repo.magento.com` | `MAGENTO_PUBLIC_KEY`, `MAGENTO_PRIVATE_KEY` in `phpbox.conf` | `m` |
| `mageos` | `repo.mage-os.org` | none | `mageos` |

The version list from `repo.magento.com` comes from the Composer v1 format (`provider-includes`), because the repository does not expose `p2/`.

`create` for 2.4.4 requires a patch version, e.g. `2.4.4-p13`. PHP is the highest version in the range: from the `product-community-edition` requirements on `create`, from `composer.lock` on `clone`. `config.platform.php` in `composer.json` takes precedence.

The search engine is selected by `_mage_services` from the Magento version and added to `SERVICES`. The `--opensearch` or `--elasticsearch` flag overrides it.

`_mage_services` sets the tag of every service given without one. Source: Adobe Commerce system requirements.

## Project from a repository

```bash
phpbox clone magento git@gitlab.example:client/shop.git --branch develop --redis --rabbitmq
phpbox db-import shop ~/dumps/shop.sql.gz
```

| Situation | Action |
|---|---|
| Custom code not ready for the highest PHP | `--php X.Y` matching the project CI |
| Database from a branch other than the cloned one | Clone the branch the dump comes from. `setup:upgrade` marks themes missing on disk as virtual (`type=1`) and Magento never restores them |

### What `db-import` does

| Step | Change |
|---|---|
| Table prefix | Detected from the `*core_config_data` table name |
| `app/etc/env.php` | Regenerated by `setup:config:set`. The `crypt` key is taken from the existing `env.php`, the old file → `env.php.<time>.orig` |
| Addresses | `base_url` → `https://<name>.localhost/`, `use_in_frontend` and `use_in_adminhtml` = `1`. Removed static/media/link URLs, `cookie_domain`, HSTS, custom admin URL |
| Multistore | A website or store with its own `base_url` gets the host `<code>.<name>.localhost`. The box nginx sets `MAGE_RUN_CODE` and `MAGE_RUN_TYPE` from maps in `boxes/<name>/nginx/` |
| Search engine | `catalog/search/*` and Smile ElasticSuite → local OpenSearch or Elasticsearch |
| Mail | `system/smtp/transport=sendmail` (to Mailpit), Mageplaza SMTP and MagePal SMTP disabled |
| Redis / Valkey, RabbitMQ | Session, cache and FPC in Redis or Valkey, AMQP to `rabbitmq`, when the service is in `SERVICES` |
| Cache | Built-in FPC without Redis. `cache:enable` turns on all types, because `setup:config:set` does not create the `cache_types` section |
| Magento | `setup:upgrade`, developer mode, `admin:user:create` from `phpbox.conf`, reindex |

A service added to `SERVICES` after `db-import` needs `bin/magento setup:config:set` with the same parameters as `magento.sh` (`--session-save`, `--cache-backend`, `--page-cache`, `--amqp-*`).
